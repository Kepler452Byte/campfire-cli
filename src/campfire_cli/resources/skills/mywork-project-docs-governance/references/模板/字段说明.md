# 模板与 frontmatter 约定

项目文档模板只在 `.claude/skills/mywork-project-docs-governance/references/模板/` 维护。其他 Skill 如需模板，应在自己的 `references/` 中维护，不建立 vault 根目录的共享模板目录。

## 所有模板的基础字段

```yaml
---
name: 文档名称
description: 一到两句话概述
type: note
project: ""
domain: ""
status: draft
lifecycle: maintained
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: []
related: []
superseded_by: []
---
```

| 字段 | 规则 |
|---|---|
| `name` | 面向阅读者的名称，应与正文一级标题一致。 |
| `description` | 一到两句话说明本文解决的问题、适用范围或当前结论，供人和 Agent 快速筛选。 |
| `type` | 文档类型，使用受控词表。 |
| `project` | 项目稳定标识。非项目文档可留空。 |
| `domain` | 项目内稳定领域。项目文档中心内必填；非项目文档可留空。 |
| `status` | 只能使用 `draft`、`current`、`archived`。 |
| `lifecycle` | 只能使用 `maintained`、`proposed`、`completed`、`archived`。 |
| `created` | 首次创建日期，格式 `YYYY-MM-DD`，创建后不修改。 |
| `updated` | 最后一次实质内容更新日期，格式 `YYYY-MM-DD`。 |
| `tags`、`related`、`superseded_by` | 必须为列表；无值时写 `[]`。 |

`status: current` 表示该文档是自身类型的当前有效版本，不代表计划已实现。实施计划或待解决问题可同时为 `status: current` 和 `lifecycle: proposed`。

## 类型与模板

| `type` | 文件名前缀或用途 | 本 Skill 资源中的模板 |
|---|---|---|
| `moc` | `MOC-` 索引 | `项目索引MOC.md` |
| `product-spec` | `产品-` | `产品文档.md` |
| `tech-spec` | `技术-` | `技术方案.md` |
| `decision` | `决策-` | `架构决策.md` |
| `plan` | `计划-` | `项目计划.md` |
| `issue` | `问题-` | `bugfix复盘.md` |
| `record` | `记录-`、会议、测试、调研 | `会议记录.md` 或按记录类型创建 |
| `note` | 通用笔记 | `通用笔记.md` |

会议可额外使用 `date`、`attendees`。类型专属字段追加在基础字段之后，不能改写基础字段的名称或语义。工作周报由 `mywork-weekly-report-writing` Skill 单独维护。

## 格式边界

统一的是 frontmatter、文件命名、日期格式和链接写法。正文不使用同一套格式：产品、技术、决策、计划、问题、会议和周报应使用各自模板的章节结构。
