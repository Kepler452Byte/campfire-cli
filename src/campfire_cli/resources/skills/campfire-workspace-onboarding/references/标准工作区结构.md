# 标准 Workspace 蓝图

只在用户明确要求按标准布局创建全新 Workspace 时使用。按这份蓝图直接执行 CLI 命令，不复制 `.campfire.yaml`、`_空间.md`、`_领域.md` 或 `.base`：它们分别由 Workspace、Space、Domain 和 Base 命令维护，不能成为可复制的第二事实源。

## 结果结构

```text
<Workspace>/
├── _收件箱/
│   ├── 用户输入/
│   └── 待接管/
├── _待用户确认/
├── _模板/                   # 新建时附带，之后由用户维护
│   ├── README.md
│   ├── 模板-任务.md
│   └── 模板-版本发布清单.md
├── _治理视图/                # CLI 管理的 Base
├── mynote/                   # 知识
├── mywork/                   # 工作
├── mylog/                    # 日志
├── myresearch/               # 研究
└── myblog/                   # 创作
```

## 执行

先创建 Workspace。它自动创建系统目录、五个标准 Space，并生成 Manifest、Space 声明、索引、Skill 路标与 Base；不要手工补写任何受管文件。

```bash
campfire workspace create --id <workspace-id> --path <path>
```

只有用户要求切换默认 Workspace 时才追加 `--default`。只在用户还需要额外 Space 时，才使用 `workspace space create` 预览并确认；不要重复创建标准 Space。

## Base 演示

创建后，`_治理视图/` 由 `campfire base sync` 维护以下开箱即用的 Obsidian Base：

- `文档工作台.base`：按类型查看当前文档、草稿和当前计划。
- `任务工作台-项目.base`：按 `related_project` 查看项目任务和阻塞任务。
- `任务工作台-个人.base`：查看不关联项目的个人任务和阻塞任务。
- `待人决策工作台.base`：查看待确认事项及人类决策状态。
- `归档文档工作台.base`：按类型或目录浏览归档文档。

它们的唯一源在 Campfire CLI 包内，更新时运行 `campfire base sync`，不要从此蓝图复制 `.base` 文件。

## 可选公开项目演示

只有用户明确要求创建 Project 演示时，使用 GitHub 公开的 [`octocat/Hello-World`](https://github.com/octocat/Hello-World)；该仓库是一个极小的公开 Hello World 示例，默认分支为 `master`。在创建 Workspace 时追加 `--demo hello-world`，CLI 会在 `mywork` 创建其文档中心，并在 `.campfire.yaml` 注册 Project 的远程地址、默认分支与根 Domain 绑定；不克隆源码，也不写设备相关的本地路径。

```bash
campfire workspace create \
  --id <workspace-id> \
  --path <path> \
  --demo hello-world
```

以后需要本地源码时，由用户自行克隆，再运行 `workspace project update --id hello-world --local-path <local-code-path>` 绑定当前设备。再按实际目标创建 `plan`、`task` 或 `record`，不要用虚构内容填满 Project Domain。

创建完成后，只有用户提供实际内容或明确组织意图时，才创建或接管 Domain。根目录 `_模板/` 默认附带模板原则 README、任务和发布清单模板；适用的格式规范卡片随实际文档保留，示例正文必须替换。模板不是实际任务或发布计划，setup/upgrade 不补写或覆盖用户模板。已有局部模板仅明确指定时使用，不给每个 Domain 复制模板。
