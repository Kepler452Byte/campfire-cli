# 工作周报写作

从实际材料形成或更新指定周期的周报，不虚构成果，不把下周计划写成已完成事项。

## 执行门禁

用户已授权撰写或更新，周期和目标唯一。材料不足时说明缺口；已有授权不重复询问，未经要求不修改历史周报。

## 上下文与契约

已知日志、上周周报或目标路径直接复用。路径未知时按类型查询现有文档，再按需查看 Domain 人工规则，不依赖固定 Space 路径。结构使用 weekly-report 的有效 Profile；正文优先采用最近 Domain 的周报模板。

## SOP

### 流程总览

```text
明确周期与写入目标
|-- 关键材料缺失 -> 说明缺口或询问，不编造成果
`-- 材料充分 -> 核对本周日志和上周计划
                |-- 同周期周报已存在 -> 读取后更新正文
                `-- 尚不存在 -> apply 创建结构 -> 按 target 写正文
                                |
                                `-- 核对事实与计划 -> 必要后续 -> 回报
```

### 执行步骤

1. 定位同周期周报，避免重复创建；已有目标不重新遍历 Workspace。
2. 读取本周日志、相关任务或用户材料，核对实际结果、问题和待办；上周周报存在时检查计划承接。首次写周报可明确注明无上周材料，不强制补造。
3. 依据本地模板组织正文；没有模板时用复盘目标、问题分析、下一步行动计划的最小结构，不写执行流水或虚构指标。
4. 新建时仅在契约未知时查询 Profile，再 apply 预览、以原输入和返回哈希确认，并按 target Edit 正文。只改已有正文直接 Edit，受管字段变化才 apply。
5. 核对周期、事实来源、计划表述和历史内容是否保留，只执行实际 follow_up。

### 命令示例

目标未知时，在已知 Workspace demo 查询周报：

```bash
campfire --workspace demo document list --type weekly-report
```

按返回路径读取候选并核对周期，不把修改时间等同于周报周期。

## 异常与停止条件

日志与用户表述冲突、同周期有多个权威候选或关键结果缺证据时询问；不为凑齐章节编造内容。发现并发修改时重新读取，不覆盖他人的新进展。

## 完成条件与回报

报告实际写入路径、对应周期和材料范围，说明未能确认的事项。正文区分已完成、进行中与未来计划，未执行的计划不算成果。
