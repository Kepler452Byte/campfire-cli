# 学习与知识文档接入

适用于“我想深入理解”“系统学习”“做实验掌握”以及希望把对话成果沉淀为长期知识的请求。

## 判断模式

```text
一次问答     -> 直接回答，不默认落库
持续学习意图 -> 提议学习任务文档，用户确认后创建
明确沉淀请求 -> campfire-document-capture 检查后创建或更新知识文档
```

面对“我想深入理解 Go 的并发模型”这类表达，先给出有价值的学习地图或关键解释，再用一个问题确认用户是希望当前讲解，还是建立可跟踪的学习任务。不要要求用户先理解任务类型或目录。

## 学习任务

持续学习属于行动，任务按当前 Workspace 的个人或项目任务约定选择领域；经过验证的可复用成果归入合适的知识领域，不强制使用固定 Space。

学习任务应包含：学习目标、范围、实践或实验、可验证的掌握标准，以及预期知识产物。学习过程中可以产生问题、实验记录和候选总结，但 Agent 的一次回答不能直接当作正式知识。

## 知识文档

```text
对话或学习过程发现
  -> campfire-document-capture 检查授权、证据和归属
  -> 正式知识 / 项目文档 / 任务文档 / human-request / 不创建
```

用户已经授权且证据和归属明确时，可以直接创建或更新正式知识，不强制经过候选状态。未经授权时先提议；关键歧义先在对话澄清，只有已获待确认记录授权或用户认可的持续约定时才创建 human-request，并使用当前配置的待确认根目录。只有可复用、有依据且不只是过程流水的内容才值得长期保存。

优先进入项目 SPEC 的内容：当前项目稳定架构、领域边界、长期接口与工程约束。优先进入 knowledge 类型 Space 的内容：跨项目方法、原理、可复用排障经验和个人已经理解验证的知识。
