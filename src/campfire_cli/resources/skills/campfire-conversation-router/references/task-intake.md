# 任务文档接入

适用于领导口头交代、IM 转述、个人待办、要求 Agent 跟进或尚不完整的执行意图。

任务计划本身是 Vault 中的 `task` 文档。本规则只把用户原话收敛为可创建的任务文档，不负责把任务交接给 Agent Session。

## 从原话到任务文档

```text
用户原话
  -> 识别来源、对象、期望结果和时间约束
  -> 搜索相关项目、已有任务和稳定文档
  -> 在当前对话形成任务建议
  -> 仅确认关键歧义
  -> 用户确认
  -> campfire-document-capture 检查写入上下文
  -> campfire-workspace-maintenance 创建正式任务文档
```

任务草案至少应让用户确认：目标、范围、非目标、验收标准、项目归属和是否允许实施。缺少普通实现细节不阻止确认；会扩大影响或改变业务方向的问题必须前置。

用户明确说“记一下”“帮我跟进”时，可以在当前对话展示任务文档建议；只有用户确认创建或跟踪后，才写正式任务文档。仅仅提到一件事情，不自动创建文档。

## 边界

任务文档记录目标、范围、验收、来源和状态，不承担 Agent Session 的分派、通信或恢复。未来即使增加 Session 协作领域，也只通过稳定标识关联任务文档，不把运行态字段塞进当前任务文档规范。

用户对创建任务文档的授权不自动包含实施、修改代码、发送消息、删除内容或扩大范围的授权。正式任务的生命周期和字段只读取 Campfire Document Profile，本规则不复述。
