# 学习与知识晋升 SOP

适用于“我想深入理解”“系统学习”“做实验掌握”以及希望把对话成果沉淀为长期知识的请求。

## 判断模式

```text
一次问答     -> 直接回答，不默认落库
持续学习意图 -> 提议学习任务，用户确认后跟踪
明确沉淀请求 -> 生成知识候选，审查后晋升
```

面对“我想深入理解 Go 的并发模型”这类表达，先给出有价值的学习地图或关键解释，再用一个问题确认用户是希望当前讲解，还是建立可跟踪的学习任务。不要要求用户先理解任务类型或目录。

## 学习任务

持续学习属于行动，任务放在 `mywork` 的个人任务体系；经过验证的成果才进入 `mynote`。

学习任务应包含：学习目标、范围、实践或实验、可验证的掌握标准，以及预期知识产物。学习过程中可以产生问题、实验记录和候选总结，但 Agent 的一次回答不能直接当作正式知识。

## 知识晋升

```text
对话或任务发现
  -> knowledge candidate
  -> 人类或 Reviewer 审查
  -> 正式知识 / 项目 SPEC / 新任务 / 合并 / 拒绝
```

知识候选说明：来源任务或对话、核心结论、证据、适用边界、建议目标领域、与已有文档的关系和未确认部分。只有可复用、经过验证且不只是过程流水的内容才值得长期保存。

优先进入项目 SPEC 的内容：当前项目稳定架构、领域边界、长期接口与工程约束。优先进入 `mynote` 的内容：跨项目方法、原理、可复用排障经验和个人已经理解验证的知识。
