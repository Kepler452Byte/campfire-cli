# 模糊任务 SOP

适用于领导口头交代、IM 转述、个人待办、要求 Agent 跟进或尚不完整的执行意图。

## 从原话到正式任务

```text
用户原话
  -> 识别来源、对象、期望结果和时间约束
  -> 搜索相关项目、已有任务和稳定文档
  -> 形成 draft 任务
  -> 仅确认关键歧义
  -> 用户确认
  -> todo
  -> 分派与实施
```

任务草案至少应让用户确认：目标、范围、非目标、验收标准、项目归属和是否允许实施。缺少普通实现细节不阻止确认；会扩大影响或改变业务方向的问题必须前置。

用户明确说“记一下”“帮我跟进”时，可以创建 `draft` 任务并在当前对话展示摘要。仅仅提到一件事情，不自动创建任务。

## 与项目工程 Task 的边界

Campfire 任务负责来源、负责人、跨 Session 状态、阻塞、审查和工作成果。软件项目内的 `tasks/TASK-*.md` 负责一次代码变更的 Goal、Scope、Constraints 和 Acceptance Criteria。

```text
Campfire Task = 工作协作事实
Project TASK  = 工程变更契约
Git           = 代码事实
```

进入软件实施前，关联而不是复制项目 Task。项目已有 `tasks/SPEC.md` 时遵守它；没有时不要擅自引入模板体系。稳定工程结论回写项目 SPEC，跨项目经验才提交为 Workspace 知识候选。

## 确认与执行

- `draft` 表示任务仍在定义。
- `todo` 表示用户已确认，可以分派。
- Agent 接受执行后进入 `in-progress`。
- 需要用户决定时进入 `blocked` 或待确认，并说明影响、选项与推荐。
- 实施结果进入 `review`，用户验收后才进入 `completed`。

用户对捕获任务的授权不自动包含修改代码、发送外部消息、删除内容或扩大范围的授权。
