# Campfire 主线任务

主线是带 `主线` 标签的 task 文档，没有专用字段、固定目录、命名或季度限制。季度主线、阶段主线和长期主线均可使用。用户或 Agent 可以不采用本 Skill，已有 Workspace 规则优先。

## 写入门禁

仅在用户授权记录或维护任务、目标唯一且内容有依据时写入。安装 Skill 或查到标签不是写入授权。位置由用户决定，已有明确位置直接复用；缺少新建位置或有多个候选时只问缺项。维护任务不等于执行任务，归档需要用户明确同意。

## 上下文与契约

- 默认用 `主线` 标签发现主线，可选性质标签为 `公司任务`、`个人项目`、`个人事务`。它们是组织约定，不是 Profile 强制枚举；用户自定义规则优先，未打标签表示未知，不归为个人事务，也不批量补标签。
- 已知文档路径直接读正文；未知时在已确定 Workspace 内查询 `document list --type task --tags 主线`，按已知项目或标签补筛选。每次 --tags 一个标签，多个标签全部匹配；查询自动对账，不先跑维护。
- 字段和状态来自有效 Profile。已有文档契约未知时 inspect，新建契约未知时 profile resolve --type task。正文直接编辑；Frontmatter、创建、改名和归属变化使用 CLI，不猜状态枚举。
- 正文保留目标与完成标准、当前待办、进展与下一步；周小节、季度分篇按用户习惯选择，不强制改造既有结构。正文待办不是第二套自动同步状态机。

## SOP

### 流程总览

```text
主线维护意图
|-- 已知路径 -> 读取正文
`-- 路径未知 -> tags 查询候选 -> 读取相关正文
    |-- 唯一且语义明确 -> 复用
    |-- 多个且无法判定 -> 询问必要差异
    `-- 无结果 -> 核实是否未打标；有新建授权与位置才创建
目标与写入授权明确
-> 维护正文或 apply 预览与确认 -> 只执行实际 follow_up -> 回报
```

### 执行步骤

1. 按当前用户意图发现候选，不周期扫描所有 Workspace。一个候选也需读正文确认用途；多结果不得默认选最新文件，零结果不得自动新建或重标旧任务。用户请求查询时只查询。
2. 分流清单时根据已有上下文匹配性质和主线，不确定的条目集中问必要问题。保留清单原意，重复条目合并到已有待办；某项本周未提及不代表取消或完成，跨周延期保留一份当前状态与必要历史。
3. 简短子项留在主线正文；需要独立状态、跨 Session 交接或独立设计资料时可建议独立 task。新建和位置仍遵循用户意图，不强制子任务与主线同域。独立子任务用 related_docs 指向主线，反向由 inspect incoming 查询，不维护对称关系；主线正文可保留链接，不复制细节或自动同步勾选状态。
4. 新建或改字段时，契约已知直接 apply 预览，无阻塞且符合授权后保持输入带回 expected_hash 与 --confirm；改路径另带 expected_plan。正文新建后在返回 target 的 `<!-- CAMPFIRE:BODY -->` 锚点后补齐，既有正文最小修改。同一 Workspace 的治理写入串行执行，不并发跑 apply、导航刷新或 Git 同步。
5. 只执行实际返回的 scoped maintenance sync，称为“导航刷新”。季度或阶段结束不自动归档、拆篇或创建下一篇；需要时按授权操作，新篇可关联旧篇追溯。

## 命令示例

假设 Workspace demo 已注册，以下只查询，不创建：

```bash
campfire --workspace demo document list --type task --tags 主线
campfire --workspace demo document list --type task --tags 主线 --tags 公司任务
```

tags 与项目名称都不表示物理目录。创建或状态维护的完整命令契约与普通任务一致，确实需要这些操作细节时参考 campfire-task-management，不为只读发现固定加载另一套流程。

## 异常与停止条件

阻塞时检查 status、issues、实际写入结果，不凭退出码宣称成功。锁占用等待操作结束后核实并重新预览，内容变化重新读取，不跳过哈希保护或无条件重试。依据不足不标完成，不能仅凭子任务关联推断阻塞或完成关系。

## 完成条件与回报

回报查询到的候选或实际更新的文档、未解决项及下一步。任务记录、导航刷新和 Git 远端同步分别按实际结果说明；远端同步遵循既有授权规则，不因维护主线自动开启。
