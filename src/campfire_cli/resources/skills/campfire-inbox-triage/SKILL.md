# Campfire 收件箱分流

为已进入收件箱的原始材料提出去向，不承担对话捕获或日常待确认事项维护。分流建议不等于移动、合并或删除授权。

## 执行门禁

只在授权范围内处理明确输入；不能确定事实或唯一归属时保留原文。新增领域、合并或删除需明确授权；待确认文档也需记录授权或用户认可的持续约定。

## 上下文与契约

收件箱与待确认区是不同用途，使用当前 Workspace 配置，不把个人目录写成通用目标。目标未知才查询 Domain 并读取相关人工规则，不固定加载 Maintenance。类型与字段以当前 Profile 为准。

## SOP

### 流程总览

```text
读取授权范围内的原始材料
|-- 事实或归属不明 -> 给出候选和问题，保留原文
|                    `-- 已授权持久记录 -> capture 创建待确认文档
`-- 去向明确 -> 提出目标与理由
                |-- 尚未授权晋升 -> 只回报建议
                `-- 已授权 -> 对应文档或重构流程 -> 核对结果
```

### 执行步骤

1. 读取原始材料，区分事实、计划和待确认信息，识别是否已有权威文档。
2. 优先选择现有正式领域，给出目标 Domain、类型、拟用标题、摘要与理由；不凭名称相似就认定归属。
3. 用户只要求盘点时到建议为止。明确授权落库后，单篇沉淀使用 document-capture，批量跨领域迁移使用 workspace-restructure；复用已确认的事实和授权。
4. 无法唯一判断时在对话集中询问。需要且获准持久记录时，在 human-request 中引用原文、列候选与明确问题，不改写原始材料。
5. 执行后只消费实际 follow_up；原文和待确认项的删除或归档分别取得授权。

### 命令示例

已知 Workspace 为 demo、需查看现有领域时：

```bash
campfire --workspace demo workspace domain list
```

使用返回的 id 与路径提出候选；查询结果不等于审批。

## 异常与停止条件

归属、权威性或合并关系有歧义时不晋升；信心高不替代审批。缺少安全移动入口时报告能力缺口，不用手工搬文件绕过结构约束。

## 完成条件与回报

明确区分已提出建议、等待确认和已实际落库，报告目标、依据、原文是否保留及未决问题。
