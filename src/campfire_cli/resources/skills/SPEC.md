# Skill Resources SPEC

本目录是 Campfire 托管 Skill 的唯一事实来源。全局 Agent Skill 目录是由 `campfire skill sync` 生成的运行副本，不在副本中直接维护托管 Skill。

## 职责边界

按用户任务选择所需 Skill，不把 Skill 名单当成必须依次执行的流水线。已知路径的正文小改直接 Edit；首次接入使用 onboarding；文档沉淀、任务维护和结构治理分别进入对应流程，仅在缺少治理上下文时加载 bootstrap。

- Skill 负责加载时机、事实门禁、业务语义和工作流程。
- CLI Profile 负责字段、枚举、类型、顺序和条件必填；Skill 不复制这些契约。
- 新建契约未知时使用 `document profile resolve --type <type>`，已有文档使用 inspect；`profile show <name>` 只接受 Profile 名，不假定 type 与 Profile 同名。
- 已知唯一存在路径的正文读取和小改直接使用文件工具，不启动 bootstrap。
- 创建正式文档、修改 Frontmatter 或显式变更类型使用 `document apply`。Frontmatter 契约已知时直接 apply；现有文档的字段类型或合法值未知时先执行一次 `document inspect`，不从 `tree`、逐层 help 或全量 Profile 探索开始。
- Markdown Frontmatter 的 `related_docs` 是受管文档关系唯一 SSOT；Skill 通过 apply 更新该字段，不解析或自动维护正文链接。SQLite、反向关系与关系页都只是可重建投影。
- 单篇 rename / move / retype 改变路径时，Skill 带回预览返回的 `expected_hash` 与 `expected_plan`；引用范围变化必须重新预览。
- 发现结构化文档集合使用 `document list`，理解单篇文档的确定关系使用 `document inspect`；两者自行 reconcile，不先运行 Maintenance。
- `document list` 不承担正文关键词、模糊匹配或相关性排序；需要正文内容时由 Agent 按返回路径读取或使用文件搜索。
- 写入命令保持原子性；Skill 只执行命令实际返回的 scoped `maintenance sync`，诊断或发布验收时再显式 `check`。
- 已存在的 Workspace、Space、Domain 和 Project 使用稳定 ID 选择；路径只用于新位置、具体文件、外部输入和显式扫描范围。
- 首次 Workspace 接入由 `workspace-onboarding` 路由；它不接管 Domain、不执行日常治理，也不修复损坏的 Manifest。

## 编写与维护规则

### 写入门禁不可因提速而省略

涉及写入的 Skill 必须在入口集中说明必要前提，放在最短路径之前，不把关键边界只藏在 references 或异常分支中：授权范围明确、目标唯一、内容表述有依据。可以简短表达，不要求加载另一套完整流程。

- 门禁是前置条件，不是固定命令序列。已有授权和证据可直接使用；仅补足缺项，不重新执行已完成的查询或索取同一授权。
- 证据要求与表述匹配：记录用户计划需标明是计划；声称功能已实现才需要对应实现证据。不得把所有文档都升级成源码审计，也不得把猜测包装成事实。
- 待确认文档也是写入，需有明确授权或用户认可的持续记录约定；仅配置存放目录不构成授权。不能以“暂存待确认”为名绕过授权，或静默记为正式事实。
- CLI 预览、Profile 校验和 `--confirm` 不证明业务事实正确，也不替代用户授权；归档、删除等专项授权边界仍有效。

### 流程与资源

Skill 同时面向 Agent 执行与人类审查，使用 [TEMPLATE.md](TEMPLATE.md) 作为可裁剪的编写骨架。每个托管 Skill 的 SOP 包含“流程总览”和“执行步骤”，流程总览用 text 代码块维护 ASCII 图，简单流程用短链。图只展示操作骨架，参数、示例与边界留在正文。标明已知信息可复用、歧义与失败停止条件，不把前提条件画成固定查询链；图文同文件、同次更新，不维护两套规则。

按任务保留执行门禁、上下文与契约、命令示例、异常与停止条件、完成条件与回报、按需参考。写入门禁用简短条件清单；只读与纯路由 Skill 可以裁剪写入或命令章节。保留必要语义，不强制凑齐标题，不添加空资源目录。模板和本 SPEC 是编写资料，不注册或分发为运行时 Skill。

1. **围绕用户任务。** description 说明何时使用、何时不用；正文写清最短步骤、完成条件和何时停下来询问。新场景优先放入已有 Skill，不因流程的一小步新增 Skill，也不在 Skill 之间来回转交同一检查。
2. **只查询缺少的上下文。** 已明确且未发生相关变化的路径、归属和字段契约直接复用；存在歧义或变化时才重新确认。项目事实需要核对项目现状，普通知识沉淀不强制检查代码仓库。沿用用户已给出的授权，只有新增风险或关键歧义才再次询问。
3. **示例必须能执行。** 假设 Agent 不会自行推断必填参数、枚举、列表格式或 Shell 引号；示例给齐必要输入，注明路径基准、预览、确认和失败语义，并通过实际执行核对关键返回字段。创建文档明确为 apply 创建结构 → 按返回的 `target` 用文件工具补正文 → 按实际 `follow_up` 完成必要维护；不虚构参数，不让 Agent 猜最终路径。
4. **每项规则只有一个来源。** 字段与枚举归 Profile，参数与返回契约归 CLI，目录约定与正文模板归 Workspace。Skill 只说明如何发现、选择和使用，不复制完整字段表，不把个人 Vault 的目录写成通用要求，不让 Agent 手写受管 Frontmatter。
5. **按需展开。** 常用步骤和安全边界直接写在 SKILL.md；特殊场景放 references，并写明何时读取。不要求先读完全部 references，不在多个文件重复同一套 SOP。
6. **变更同步验证。** CLI 契约变更时检查受影响的 Skill、references 与 Agent Hint，只修改确实受影响的内容。修改托管资源后运行 Skill 检查；涉及安装分发时通过 `campfire skill sync` 同步并核对运行副本，不直接修改副本。标准文档修改本身不要求同步安装。

## 验收方式

- 在隔离的测试 Workspace 中实际执行受影响的命令示例，核对参数、关键返回和最终文档；不以整段帮助文案或输出快照作为契约。
- 影响工作流时，用少量对应的自然语言任务核验调用序列、必要提问和最终结果；重点检查重复发现、无效参数及越过授权边界。命令示例通过不等于 Agent 场景已验收。
- 门禁审查至少覆盖：授权与事实充分时直接执行；无写入授权时不落盘；目标或关键事实不明时停下来澄清；用户计划不被记为当前实现。不能只验证成功路径的命令次数。
- 沿用现有测试和验收记录，不新增通用评测框架、不为每个 Skill 维护版本字段；按模板整理时保留业务与安全边界，不把标题、整句文案或 ASCII 排版作为运行契约。
