# 工作周报写作

适用于 `mywork/【工作日志】文档中心/工作周报/` 下的工作周报。输出应延续现有周报的简洁、成果导向和技术复盘风格。

## 输入与依据

1. 读取本周工作日志，确认完成事项、实际结果、已发现问题和待办。
2. 读取上一周周报，识别本周工作的承接关系，并检查上周计划的进展。
3. 需要详细的既有写作要求时，读取[周报写作提示词](references/周报写作提示词.md)。该文件是 Skill 的参考资源，不再作为工作周报目录中的独立提示词维护。
4. 若缺少工作日志、周期或上周周报，明确指出缺失信息；不要编造工作成果、技术难点、指标或计划。

## 输出规则

- 文件名使用 `邵元宏-工作周报-YYYYMMDD-WN.md`。`YYYYMMDD` 取周报周期结束日，`WN` 延续当期周序号；日期或周序号无法确认时先询问。
- 新建时使用[工作周报模板](references/工作周报模板.md)，并填写 `period`、`created`、`updated` 与上一期周报的 `related` 链接。该模板只在本 Skill 的资源目录维护。
- 正文固定为 `复盘目标`、`问题分析`、`下一步行动计划` 三部分。不要改为日记流水账，也不要混入无关背景。
- `复盘目标` 先用一段话交代与上周的承接，再按工作主题归纳 3 至 5 项完成成果。每项说明做了什么、产生了什么能力或结论。
- `问题分析` 只分析本周已发生或已经识别的技术难点、取舍、风险和根因；说明影响与判断依据。
- `下一步行动计划` 从未完成工作、风险和本周成果自然推出，写出可交付的下一步，不虚构日期、负责人或指标。

## 写作边界

- 工作日志是事实来源；上周周报只用于承接上下文，不能覆盖本周事实。
- 计划中的工作必须明确为计划，不能写成已完成。
- 指标必须来自日志、报告或用户提供的材料；没有证据时使用定性描述。
- 除非用户明确要求，不修改历史周报；新建周报前先检查同周期文件是否已存在。
